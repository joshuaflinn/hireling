## Why

E4, Phase 0: the rules-corpus importer is the data foundation the buff engine (E8) is judged against — fidelity is the whole job. Built from the approved spec/brainstorm/plan artifacts in `specs/004-rules-corpus-importer/`; no scope left the P0 line.

## What

- **Importer CLI** (`src/import/`): `hireling import --release <tag>`, `license-archive --release <tag>`, `license-verdict`; `just import|license-archive|license-verdict` wrappers. Hand-rolled argv parsing (two subcommands and a flag don't justify clap — Constitution Art. V).
- **Thin shell / pure core**: fetch (pinned tag, sha256-verified asset, bounded retry + jitter, whole transfer inside the loop) → extract+validate ALL before any write → pure plan → one transaction per category → structured run report (JSON log + human render).
- **Tier seed** `data/seed/condition-tiers.json` ships **frightened** as engine-math (the fixture-verified case) and **concealed** explicit display-only. Everything else defaults display-only and is named in every run report for the owners' seed PR — deliberately not model-authored; fabricating 40 mappings from memory is exactly what Article IV forbids, and the report makes the coverage gap visible instead.
- **License gate**: `NOTICE.md` (with machine-readable `license-coverage:` block), upstream ORC/OGL texts archived at the pinned release with sha256s in `SOURCE.md`, green/red verdict gating public exposure.
- **Seed-correction convergence**: a stored tier that disagrees with the seed's current verdict re-plans on the next run even when hash and importer version match — retiring engine math can't survive a re-run by accident, and needs no version bump.
- **E2 adaptation** (per the design's own rule "E2's migrations are authoritative and E4 adapts"): provenance lives in `data.import`, mappings in `modifiers` (FG3 shape + one `value_kind` extension for valued conditions), the run report replaces the declined `import_runs` table, and **E4 ships zero migrations** — integration tests apply `tests/schema.sql`, a labeled copy of E2's `20260924000004_corpus.sql` (+ the `accounts` stub its FK needs), to be swapped for `sqlx::migrate!` when E2 lands on main. Recorded in the plan addendum; flagged here for review.
